# OUT-32 performance contract and evidence

The current product exposes chats, diffs, provider choices, and worktree navigation. Native workflow history, event inbox, review chapters, and role output have no UI or persistence path on this branch; their future owners must apply the same bounded view and state rules when those surfaces arrive. OUT-30 owns backend quotas.

| Surface and owner | Main risk | Contract and focused evidence |
| --- | --- | --- |
| Chat history in `src/App.jsx`, `src/components/WindowedMessages.jsx`, `src/recovery-policy.js`, `server/database.mjs`, and `server/outright-runtime.mjs` | Pagination, late events, resizing, or recovery moves the reading anchor; offscreen and older messages become unfindable | Keep at most 1,000 client messages, 2,048 checkpoint cursors, 20 tool events, and a 2 MiB pending event buffer. A 1,000-message fixture mounts fewer than 40 rows, scrolls to both ends in under 1 s, finds matches near both ends, and preserves the anchor on prepend. Growing and shrinking the viewport retain a found tall row; first and last find matches stop aligning at the scroll clamp, and later wheel scrolling stays owned by the reader. Uncaught browser errors fail the fixture. Conversation-scoped find returns at most 200 persisted rows around a match; next/previous wrap through older pages. Forward pages use a conversation-scoped `after` cursor and bounded 200-row requests so an old match can be read continuously through the persisted end; empty and foreign cursors retain exact count and error semantics. Its status and list semantics use persisted positions and total, including old and new pages. A sparse search with 500,000 sibling messages stays responsive, and legacy rows migrate to the indexed conversation order. Unicode find works across old and new pages; the focused find bar stays visible and live append does not return the reader to an old match. Missed replay, completion, and list refresh retain the reading anchor; overlapping checkpoint bodies refresh in place, while unseen rows expose Return to latest. A conversation-scoped count read reconciles repeated live ids and off-page checkpoint rewrites with persisted totals. Events captured during a find remain reachable after its response. Both Return to latest/Find response orders are fenced. Typing without navigating does not cancel an earlier-page request. Explicit return loads the persisted latest page. A 10,000-event replay completes under 250 ms and returns the newest 1,000. |
| Git diff and mutations in `src/components/ChangesPane.jsx`, `src/components/WindowedDiff.jsx`, and `server/git-service.mjs` | The real inspector lets the diff viewport grow to full text height; stale stage, unstage, commit, status, or diff completion crosses a worktree switch | The 448 px production column bounds a 50,000-line staged and unstaged diff below 200 mounted spans, retains visible mode controls, reaches the final line by wheel and End key, and marks an offscreen find match. Unicode case folding keeps diff matches on their original line. A 320 px inspector remains bounded. File and mode selection clear the prior diff before a pending request, including a failed response. Same-selection background/manual refresh retains the old text and visible line until the response, retains find through identical or changed text, and keeps the last valid text on failure. Mutation completion is fenced by worktree generation before a refresh, toast, error, or state commit; late unstage failure is covered explicitly. The existing 12 MiB Git command output bound still applies. |
| Provider discovery in `server/provider-discovery.mjs`, `src/App.jsx`, and `server/outright-runtime.mjs` | A missing CLI remains falsely unavailable after install or falsely available after removal; a checking bootstrap misses its only event or polls without delay; trust is revoked during the provider await | Display discovery is cached per provider with one in-flight probe per CLI, a 2.5 s process timeout, 30 s refresh interval, and shutdown cleanup. Send and recovery authorization await a fresh requested-provider probe before durable commits; a successful in-flight probe is reused without a second serial process, while an old negative is retried. The child process is asynchronous, so the Node event loop stays responsive. A 250 ms executable probe through each real HTTP endpoint has a 2.5 s request budget and at least five 20 ms event-loop ticks while pending. A requested provider never waits for an unrelated hung CLI. A checking bootstrap polls no faster than once per second until settled. Send and recovery recheck trust just before their durable commits, along with target identity and recovery order. |
| Worktree navigation and live output in `src/App.jsx` | Repeated switches mount hidden chats or every delta repaints the root | A 200-worktree fixture switches sixteen times under 6 s, keeps one conversation mounted, records heap at the start, midpoint, and end, rejects growth over 64 MiB, and returns an input frame under 250 ms. A 200-delta fixture preserves all output, bounds paints by elapsed stream time at a 24 ms cadence plus eight frames (at most 100), and returns an input frame under 250 ms. Assistant delta painting is coalesced at 32 ms while checkpoint and final messages flush immediately. |

Sibling operations and state changes considered: chat selection, older-page prepend, return to latest, no-match and failed find, WebSocket replay and missed replay, staged/unstaged and file changes, stage/unstage/commit success and failure, recovery retry/resume/discard, trust grant/revoke, provider install/removal/failure, and shutdown during a probe. Malformed find queries and foreign message cursors fail before page navigation; unknown providers remain unavailable. Concurrent search and mutation responses are fenced to the selected conversation or worktree. The runtime owns authorization and durable run state; the database owns bounded page retrieval and indexed search; the view components own DOM windowing and keyboard navigation. Provider probing uses `execFile` with `windowsHide`; the Windows `CreateProcessW` supervisor launches executable files but not npm `.cmd` shims, so that existing platform limitation is not claimed as supported by this Mac evidence. Linux and Windows process cleanup paths are covered by targeted tests and static review, not execution on those hosts. Native workflow history, event inbox, review chapters, and role output are absent on this branch, so their future owners must apply this contract when those surfaces are built.

Latest review risk matrix: viewport edge and scrollbar interaction can keep an alignment frame loop alive; page replacement can drop a replayed checkpoint, live find event, or a reader-selected older page; checkpoint updates outside the loaded page can inflate counts; a new row at the 1,000-message cap can evict the reader's visible anchor; a failed diff request can show the prior file under a new label; and a provider probe can add submit latency even while leaving the event loop free. The focused browser cases exercise first/last matches, reconnect and completion, list refresh, in-flight find, repeated off-page updates, typing during prepend, the full-page live anchor, and failed file/mode switches. The executable-probe HTTP tests cover send and recovery with a slow provider and event-loop progress. Interruption, malformed query, authorization, and platform boundaries retain the earlier tests and limitations above.

Latest repair risk matrix: same-file/mode refresh must retain diff text, line and find across identical content, changed content and failure; changed file/mode must clear ownership immediately. Return to latest and Find can finish in either order; a no-op older checkpoint must not set a future scroll restoration; list, reconnect and completion reads must preserve an older page. Forward paging must cross old and new pages without gaps or duplicate rows, keep the 1,000-row cap, preserve the visible anchor while it remains in the window, and reject foreign or conflicting cursors. Persisted totals must reconcile repeated off-page checkpoint updates and multiple new ids; the lightweight count read is scoped to one conversation and throttled during output. A requested provider's successful in-flight probe must avoid a second 2.5 s wait, while a failed in-flight probe must retry after install. The focused database, provider and browser cases distinguish these contracts from the prior behavior; the existing tests cover file/mode switch failures, reconnect, malformed search, trust/recovery fences and platform process cleanup. Mac fixture evidence does not establish Windows/Linux CLI execution or a multi-hour memory trend.

The local preview opened in Aside Browser and returned HTTP 200 for the app, bootstrap and providers API; 50 live provider reads measured 0.27 ms median and 2.11 ms p95.
