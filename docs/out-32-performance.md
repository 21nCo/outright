# OUT-32 performance contract and evidence

The current product exposes chats, diffs, provider choices, and worktree navigation. Native workflow history, event inbox, review chapters, and role output have no UI or persistence path on this branch; their future owners must apply the same bounded view and state rules when those surfaces arrive. OUT-30 owns backend quotas.

| Surface and owner | Main risk | Contract and focused evidence |
| --- | --- | --- |
| Chat history in `src/App.jsx`, `src/components/WindowedMessages.jsx`, `src/recovery-policy.js`, and `server/database.mjs` | Pagination, late events, resizing, or recovery moves the reading anchor or retains too many messages | Keep at most 1,000 client messages, 2,048 checkpoint cursors, 20 tool events, and a 2 MiB pending event buffer. A 1,000-message fixture mounts fewer than 40 rows, scrolls to both ends in under 1 s, and preserves the visible anchor when loading an older page. A 10,000-event replay completes under 250 ms and returns the newest 1,000. |
| Git diff in `src/components/ChangesPane.jsx`, `src/components/WindowedDiff.jsx`, and `server/git-service.mjs` | Large text creates thousands of DOM spans, or a late response replaces the selected file | A 50,000-line diff mounts fewer than 200 spans and reaches its final line in under 1 s. File and staged mode requests have a generation fence. The existing 12 MiB Git command output bound still applies. |
| Provider discovery in `server/provider-discovery.mjs`, `server/agent-manager.mjs`, and `server/outright-runtime.mjs` | A version subprocess blocks bootstrap or run submission; a missing CLI is accepted | Cache probes outside requests with one in-flight refresh, 2.5 s process timeout, 30 s refresh interval, and shutdown cleanup. Requests read the snapshot; an initial run authorization waits asynchronously for discovery. Both send and recovery still validate trust and durable target identity after awaits. |
| Worktree navigation and live output in `src/App.jsx` | Repeated switches mount hidden chats or every delta repaints the root | A 200-worktree fixture switches eight times under 3 s, keeps one conversation mounted, and returns an input frame under 250 ms. A 200-delta fixture preserves all output, paints fewer than 50 times, and returns an input frame under 250 ms. Assistant delta painting is coalesced at 32 ms while checkpoint and final messages flush immediately. |

Other relevant transitions include switching chats while a detail request is pending, reloading after a WebSocket gap, staging or unstaging a diff, retrying a failed provider check, stopping a run, and shutdown during a probe. Empty diff and unknown provider inputs retain their existing safe results. Provider detection runs through `execFile` on macOS, Linux, and Windows; Windows hides the probe process window. Authorization, recovery, and target fencing remain with the owning runtime service.

Measured on Mac16,7 with Node 20.20.0 and headless Chrome 153.0.8010.48: 1,000-message navigation 50 ms with 10 rows mounted; 50,000-line diff navigation 31 ms with 69 spans mounted; 200 output deltas coalesced to 23 paints with an 11 ms input frame; eight switches among 200 worktrees took 333 ms with a 17 ms input frame. Fifty live `/api/providers` requests had 0.44 ms median and 1.06 ms p95 response time. Browser heap snapshots are logged by the fixture but vary with garbage collection and are not used as a pass criterion. The local preview opened at `http://127.0.0.1:5177/`; automated Chrome interaction covers the representative journeys. No manual assistive-technology session or workload longer than these fixtures was performed.
