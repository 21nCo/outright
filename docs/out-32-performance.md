# OUT-32 performance contract and evidence

The current product exposes chats, diffs, provider choices, and worktree navigation. Native workflow history, event inbox, review chapters, and role output have no UI or persistence path on this branch; their future owners must apply the same bounded view and state rules when those surfaces arrive. OUT-30 owns backend quotas.

| Surface and owner | Main risk | Contract and focused evidence |
| --- | --- | --- |
| Chat history in `src/App.jsx`, `src/components/WindowedMessages.jsx`, `src/recovery-policy.js`, `server/database.mjs`, and `server/outright-runtime.mjs` | Pagination, late events, resizing, or recovery moves the reading anchor; offscreen and older messages become unfindable | Keep at most 1,000 client messages, 2,048 checkpoint cursors, 20 tool events, and a 2 MiB pending event buffer. A 1,000-message fixture mounts fewer than 40 rows, scrolls to both ends in under 1 s, finds matches near both ends, and preserves the anchor on prepend. Growing and shrinking the viewport retain a found tall row, and uncaught browser errors fail the fixture. Conversation-scoped find returns at most 200 persisted rows around a match; next/previous wrap through older pages. Its status and list semantics use persisted positions and total, including old and new pages. A sparse search with 500,000 sibling messages stays responsive, and legacy rows migrate to the indexed conversation order. Unicode find works across old and new pages; the focused find bar stays visible and live append does not return the reader to an old match. Missed replay and run completion retain the reading anchor while exposing a visible Return to latest control; an explicit return loads the persisted latest page. Find, prepend, and return-to-latest requests own separate page generations so late responses cannot replace a newer choice. A 10,000-event replay completes under 250 ms and returns the newest 1,000. |
| Git diff and mutations in `src/components/ChangesPane.jsx`, `src/components/WindowedDiff.jsx`, and `server/git-service.mjs` | The real inspector lets the diff viewport grow to full text height; stale stage, unstage, commit, status, or diff completion crosses a worktree switch | The 448 px production column bounds a 50,000-line staged and unstaged diff below 200 mounted spans, retains visible mode controls, reaches the final line by wheel and End key, and marks an offscreen find match. Unicode case folding keeps diff matches on their original line. A 320 px inspector remains bounded. Mutation completion is fenced by worktree generation before a refresh, toast, error, or state commit; late unstage failure is covered explicitly. The existing 12 MiB Git command output bound still applies. |
| Provider discovery in `server/provider-discovery.mjs`, `src/App.jsx`, and `server/outright-runtime.mjs` | A missing CLI remains falsely unavailable after install or falsely available after removal; a checking bootstrap misses its only event or polls without delay; trust is revoked during the provider await | Display discovery is cached per provider with one in-flight probe per CLI, a 2.5 s process timeout, 30 s refresh interval, and shutdown cleanup. Send and recovery authorization force a new requested-provider probe after any older in-flight probe, so removal and reinstall are both seen before durable commits and an unrelated hung CLI cannot delay authorization. A checking bootstrap polls no faster than once per second until settled. Send and recovery recheck trust just before their durable commits, along with target identity and recovery order. |
| Worktree navigation and live output in `src/App.jsx` | Repeated switches mount hidden chats or every delta repaints the root | A 200-worktree fixture switches sixteen times under 6 s, keeps one conversation mounted, records heap at the start, midpoint, and end, rejects growth over 64 MiB, and returns an input frame under 250 ms. A 200-delta fixture preserves all output, bounds paints by elapsed stream time at a 24 ms cadence plus eight frames (at most 100), and returns an input frame under 250 ms. Assistant delta painting is coalesced at 32 ms while checkpoint and final messages flush immediately. |

Sibling operations and state changes considered: chat selection, older-page prepend, return to latest, no-match and failed find, WebSocket replay and missed replay, staged/unstaged and file changes, stage/unstage/commit success and failure, recovery retry/resume/discard, trust grant/revoke, provider install/removal/failure, and shutdown during a probe. Malformed find queries and foreign message cursors fail before page navigation; unknown providers remain unavailable. Concurrent search and mutation responses are fenced to the selected conversation or worktree. The runtime owns authorization and durable run state; the database owns bounded page retrieval and indexed search; the view components own DOM windowing and keyboard navigation. Provider probing uses `execFile` with `windowsHide`; the Windows `CreateProcessW` supervisor launches executable files but not npm `.cmd` shims, so that existing platform limitation is not claimed as supported by this Mac evidence. Linux and Windows process cleanup paths are covered by targeted tests and static review, not execution on those hosts. Native workflow history, event inbox, review chapters, and role output are absent on this branch, so their future owners must apply this contract when those surfaces are built.

Latest full browser fixture on Mac16,7 with Node 22.22.1 and headless Chrome: 1,000-message navigation and find in 455 ms with 10 initial rows; 50,000-line diff navigation in 72 ms with 66 mounted spans; 200 deltas in 2,308 ms with 46 paints against a rate-adjusted budget of 100 and a 5 ms input frame; sixteen switches across 200 worktrees in 1,240 ms with one mounted conversation and a 9 ms input frame. Heap samples across the two switch cycles were 69.5, 73.6, and 78.5 MiB. Garbage collection makes this a trend sample; the 64 MiB fixture bound catches large regression growth but does not prove multi-hour stability. A 500,000-message sibling fixture passes a 35 ms median bound for three sparse no-match searches and one older-page read. A 10,000-message, 224-byte-body no-match Unicode search previously measured 3.51 ms median and 4.42 ms p95 over ten in-memory database reads. The local preview opened in Chrome and returned HTTP 200 for the app, bootstrap and providers API; 50 live provider reads measured 0.30 ms median and 1.34 ms p95. Manual spoken screen-reader behavior remains deferred to OUT-45.
